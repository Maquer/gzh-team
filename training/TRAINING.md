## 0. 培训的定义（先划边界，否则培训落不到任务时）

培训 = 把**可判定的能力项**注入到任务时 + 用脚本判定达标 + 记录差距。

**不等于**：写课程文档、开培训会、设学分、设培训时长。这些都是纸面培训——
岗位是 prompt 驱动的，没有任何"加载"动作的培训，对产出的影响是零。

三条硬边界（来自 VALIDATION.md 的 6 次实验 + 7 模型全失败实测，不是设计偏好）：

1. **精确计数类能力不写进技能卡**（字数/句数/金句数/占比）。
   实测：模型 5/5 次都超 3 句段限制，且自报"1560 字"实为 1131（虚高 38%）。
   写进卡也不会遵守，因为约束在输出之后才失效。
2. **技能卡只写布尔判断类能力项**（有没有某标记、某节、某个链接）。
   实测：布尔判断 5/5 次 100% 遵守。这类才适合让模型自检。
3. **训练效果只用 train-check.py 判定**，不接受"感觉更好了"。
   模型自评不可信（VALIDATION §9：精确计数类必失败，且失败时不报错）。

## 1. 培训机制（三层，缺任何一层都不闭环）

```
技能卡（skills/*.md）      任务派发时注入 prompt    —— 教的载体
        ↓
train-check.py            产出后用脚本判达标        —— 度量
        ↓
TRAINING.md §2 基线表     差距 → 培训动作 → 复测     —— 闭环
```

**关键**：技能卡的内容必须能被 train-check.py 判定。如果卡上写了一条能力项，
脚本里找不到对应检查，那条能力项就是纸面的——不允许这样写。

## 3. 培训动作（差距 → 动作 → 复测）

### 动作 1：H14 AI 味（唯一实测缺口，P0）

- **差距**：4 篇稿件 AI 味 11-25 分，全在"重写≥50%"区
- **动作**：主笔产出后跑 `train-check.py`（内部调 humanizer-check v2，lieflat 11 条实证规则），
  按 §2 H14 阈值判定：≤5 放行 / 6-15 重写≥50% / >25 推倒重写
  **阈值没变，判定档位变了（2026-09-18）**：默认 `--mode solo`，H14 走 SKIP——
  分数照常显示但不卡关，人工看分数决定是否改稿；`--mode strict` 保留三档硬判定，
  用于审核岗独立评审与发布前检查。改理由见 §7 动作 1 复测：改稿循环在此模型下执行不了
  （99.8% 原样回显），硬门禁只会逼人绕门禁。
  **实测验证**：3 篇历史稿 solo 全 100% 通过 exit=0；strict 仍 89%/89%/83% 卡住，同一稿只这一项不同
- **不要做的**：把 AI 味规则写进技能卡让模型自检。实测无效——精确计数类
  和主观评分类都不可靠，这条属于"必须外部脚本判"
- **复测**：改稿后再跑一次，记录分数变化到本表

### 动作 2：技能卡注入（P0，机制层）

- **差距**：company-mode.py 的 ROLES 是 6 个通用后端
  （coding/writing/research/decision/explain/default），与 8 个岗位不对应。
  所以即使写了技能卡，任务派发时也不会被加载——培训无法落地
- **动作**：company-mode.py 加 `GZH_ROLE_CARDS` 映射（岗位 → 技能卡路径），
  派发时把技能卡全文拼进该岗位的 prompt
- **复测**：跑一次 company-mode 派发，确认技能卡内容真的出现在 prompt 里

### 动作 3：H10 结构漂移检测落地（P1，已在 train-check.py 实现）

- **差距**：REVIEW.md 有 H10 门禁，但 gate-check.py 未实现
- **动作**：已在 train-check.py 实现（含文件类型识别：正文片段不判包装节）
- **已知口径坑（已踩）**：正文片段（clean 版）不该判 H10 / AI 参与声明 /
  标题策略三项，否则假阳性。已用三态判定（PASS/FAIL/SKIP，SKIP 不计入分母）

### 动作 4：7 岗基线补测（P1，需模型调用）

- **差距**：7 岗零实测数据
- **动作**：每岗跑 ≥3 个真实任务样本，用 train-check.py 或对应工具取数
- **阻塞**：交叉验证曾 6 模型全失败并达停手上限（VALIDATION §9），
  补测前需先确认模型可用性，且样本数不足 3 不出结论

## 4. 结业标准

| 档位 | 标准 | 判定 |
|------|------|------|
| 达标 | 可判项通过率 100%（SKIP 不计入分母） | train-check.py exit 0 |
| 需改进 | 有 FAIL 项，但不在"推倒重写"区 | 记录差距，下一轮复测 |
| 不达标 | 任一门禁项 FAIL（strict 模式下含 H14） | 退回重做，不进下一段 |
| 需人工决策 | solo 模式下 H14 >25 分（推倒重写区） | 单人模式不自动退回，由负责人看分数决定 |

**禁止**：用"感觉"或"整体不错"替代通过率。没有数字的结业判定不算结业。

### 核心发现

1. **角色卡约束有效，画像口头禅无效**——"未越界写正文"8/8 PASS 说明角色卡的核心约束（不越界写稿）生效；但口头禅和灵魂关键词 0/8 说明 1 行注入被 3-4KB 卡体淹没，模型不会主动"说出口头禅"。**结论：画像注入提升了角色辨识度（人类可读），但未改变模型行为。**

2. **train-check.py 对非正文产出有系统性假阳性**——8/8 角色 FAIL H8 字数，但审核报告/排版说明/发布清单天然不到 800 字。5/8 角色 FAIL H9 段落≤3句，但结构案/数据分析报告天然多句段落。**这是 train-check.py 的设计缺陷——它假设所有产出都是正文，需要按岗调整。**

3. **禁用词和紧迫词仍有命中**——09 数据分析师命中"其次"（禁用词），02 选题规划师命中"震惊"（紧迫词）。与第 3 次培训（09-20）基线一致，画像注入未改变语言习惯。

## 6. 修订记录（2026-09-18 实测后更新）

### 动作 2 修订：不改造 company-mode.py，培训体系自建派发入口

原方案（§3 动作 2）是改 company-mode.py 的 ROLES 加 8 个岗位。实测后放弃，改自建：

   锚点定位不可靠——不值得为一个培训接线去赌共享基础设施
3. 自建入口可以把「岗位 → 后端」的近似映射显式写出来（ROLE_BACKEND），
   而不是混在通用 ROLES 里让人分不清哪个是岗位、哪个是后端

**已验证（功能测试，非推断）**：
- T1 带卡：prompt 含卡片标题 + 具体条款（段落用空行分隔）✅

- T4 8 个岗位技能卡全部可加载 ✅
- T5 注入后 prompt 约 728 字符（0.71KB），在注入预算内 ✅

用法：`python3 training/gzh-dispatch.py "写公众号正文" --role-card 02-主笔 --dry-run`

### 结论

1. **布尔判断类能力项，技能卡有效**——标题策略做到 0/3 → 3/3 的完全分隔，

   布尔类模型做得到，写进卡就遵守。
2. **AI 味，技能卡无效**——均值差 +1.0 分，被 B 组自身 15 分摆幅完全淹没。

   **要治 AI 味只能靠改稿循环（humanizer-check 打分 → 按条重写），不能靠培训卡。**

### 方法学教训

- **噪声底必须先量**：B 组同条件重抽摆幅 15 分（20/27/35），任何 n=3、

- **第一轮结论被我自己的 4 个检查器缺陷污染**，逐个修掉后数字才稳定：
  1. 金句按【金句】计数，约定其实是加粗（已修）

     导致 B 组从真实的 5/5 被误读成 0/5（已放宽为四种等价写法）

     结尾内容被算进正文，H8 系统性虚高约 60-300 字

## 9. Pattern Learning：角色卡自增长（2026-09-19 落地）

### 机制

每张技能卡末尾有两个生长段 `## 成功模式` + `## 失败模式`，每次稿件交互后追加新
洞察。`gzh-dispatch.py` 逐字读卡片注入 prompt → **下次派发自动带出全部历史 pattern**，
派发链路零改动。

### 工具

```bash
# 追加 pattern（自动去重 + FIFO 淘汰，每段上限 12 条）
python3 role-patterns.py add --role 02-主笔 --type effective|anti --text "..."

# 查看单角色 / 全量
python3 role-patterns.py list --role 02-主笔
python3 role-patterns.py list --all

# 跨角色关键词检索（agent-tagged recall）
python3 role-patterns.py recall --query "标题 策略"
python3 role-patterns.py recall --query "门禁" --role 02-主笔

# 清理超期
python3 role-patterns.py prune --days 90

# 初始化空段
python3 role-patterns.py init
```

|------|------|------|
| 01-选题规划师 | 🔴 | 选题无数据支撑不做，先补数据再评估 |
| 02-主笔 | 🟢 | 标题策略名必须写成（缺口）括号分隔 |

### 与 §7 A/B 实测的关系

§7 证明"培训卡能否改善产出"在单模型下不可行（99.8% 原样回显）。Pattern Learning
是**不同机制**：它不是让模型学会改写，而是把**已验证的教训写进下次 prompt**，让
模型在生成前就知道哪些坑不能踩。这是静态知识注入，不依赖模型执行"改"的能力。
