# 宇龙「Claude Project 三原则」vs gzh-team 我们的机制

> 来源：https://mp.weixin.qq.com/s/Jw4czA9Pr2KXfDEF_O1iKw（宇龙 AI · 2026-09-19）
> 触发：讨论是否把「专属记忆本 / 隔离沙盒 / 自检闭环」搬进我们工具链
> 结论：3 层原则**部分重合、部分我们更强、部分我们完全没有**，但宇龙真正遗漏的 4 层才是 gzh-team 护城河

---

## 1. 三层原则对照

| 层 | 宇龙版（Claude Project 转述） | gzh-team 对应机制 | 我们的优势 | 我们的空白 |
|----|------------------------------|------------------|-----------|-----------|
| **记忆** | 建"专属项目文件夹" + `rules.txt` 写业务规则；每次开工先让 AI 完整读它 | TEAM.md 8 岗位职责表 + `training/skills/*.md` 9 张技能卡 + 每岗画像（司南/探微/林墨…）+ `baselines/*.json` 实测基线 | **多角色分工规则**（宇龙是单 Agent 业务规则）；规则有明确归属人；有 baselines 实测数字 | 单点启动时画像触发率 0/8（09-21 第四次培训实测），跨会话记忆不稳 |
| **沙盒** | 建 `temp/` 子文件夹，死命令"严禁修改上级目录"，改废清空重来 | **无对应机制**——我们的稿件本身就是临时产出，不碰用户原始源文件 | 我们不需要（不同工作形态） | 若接入外部用户源文件（表格/素材），无沙盒约定 |
| **自检** | 提示词末尾焊「自检要求：从头到尾复核 3 遍」，然后列核验明细再交付 | `gate-check.py`（H1-H14 维度 + 占位符 + 紧迫词 + 越界红线）+ `train-check.py` + `link-check.py` + `verify-all.py` | **脚本化 30+ 维度硬门禁**，不靠模型自觉；一票否决阻断；有 VALIDATION 4 篇实测数据 | H14 维度仍有系统性假阳性（09-21 第四次培训 8/8 FAIL） |

## 2. 宇龙**遗漏**的 4 层（我们的护城河）

宇龙的文章没提，因为它的目标是"教小白用 AI 工具"，不是"建多人协作流水线"。这 4 层是 gzh-team 独有的：

### 2.1 单职责 + 越界红线

宇龙让一个 Agent 干完所有事；gzh-team 拆 8 岗，每岗写"不做什么"：
- 主笔："改结构 = 同时扮演审核，流水线门禁失效"
- 审核："不重写、不美化句子。自己改完自己审 = 自嗨"
- 排版："顺手改 = 审核白做"
- 负责人："手不碰字，嘴只说'重做'"

**理由**：单 Agent 的自检是"自己给自己打分"，天然有偏；分工 + 交叉审才是硬约束。

### 2.2 门禁不可跳过

宇龙靠"提示词焊死自检指令"，本质是让 AI 自己承诺；gzh-team 的 `gate-check.py` 是**外部脚本**，AI 无法绕过——一票否决 FAIL 就停。

### 2.3 交接物标准化

每岗产出物有字段规范（如主笔必须交付：正文 800-1200 字 + 备选标题 5 个 + 金句 3-5 处 + 配图指导），`[待填写]` 占位符必须文末追加"信息缺口声明"。宇龙完全没有。

### 2.4 画像驱动跨会话注入

8 个岗位各有名字（司南/探微/梁木/林墨/鉴之/织锦/渡舟/连桥/明镜）+ 人格画像 + 训练基线。宇龙是"每次开工先读 rules.txt"——一次性注入，不做持续学习。

## 3. 可借鉴（宇龙做得比我们好的地方）

### 3.1 「严禁修改上级目录」这句硬指令

我们没写。我们的工具是"在固定目录产出稿件"，但如果未来接入用户源文件（Excel/素材库），这句硬指令值得搬。

**建议**：加到 `docs/rules/01-sandbox.md`（新建）或 `TEAM.md` 门禁硬规则段。

### 3.2 「先列核验明细再交付」的产出结构

宇龙的自检指令强制"自检确认无误后，先列出修改与核验明细，再交付最终成果"。我们 `gate-check.py` 目前只输出 PASS/FAIL，不输出"修改明细"。

**建议**：`gate-check.py` 加 `--verbose` 模式，输出每维度得分 + 修改建议，不只给二值。

### 3.3 「从 X 到 Y」的工作流进化叙事

宇龙结尾用「全天候监工 → 甩手掌柜」做工作流进化叙事，读者易共鸣。我们缺这种"用户视角的价值故事"。

**建议**：不做。我们不是给小白看的入门内容，是给团队自己用的规则文档。

## 4. 落地决策

| 项 | 决策 | 理由 |
|---|------|------|
| 借鉴 3.1 沙盒硬指令 | ⏸ 暂缓 | 我们目前不接入用户源文件；等真实需求出现再加 |
| 借鉴 3.2 自检明细输出 | ✅ **已落地** | 2026-09-21 加 `gate-check.py --verbose`：核验明细表 + 未跑检查段 + 逐项修改建议 + 自检覆盖统计（10/10 已跑） |
| 借鉴 3.3 用户视角叙事 | ❌ 不做 | 定位不同 |
| 保留我们 2.1-2.4 护城河 | ✅ 不动 | 已落地并有实测数据 |
