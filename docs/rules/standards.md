# 数值标准

> 位置：gzh-team 外部规则层 | 维护人：负责人 + 主笔 | 更新频率：数据复盘后调整
> 建库时间：2026-09-20 | 依据：v1.6 架构调整"职责与规则分离"

## 适用范围

所有主笔产出的正文内容（Markdown 成稿）。

## 标准清单

### 1. 正文长度

> **v2.0 政策变更（2026-09-24 A 级决策）**：字数不再设硬上下限，按题材判合理性。以下档位仅作**参考锚点**，不 FAIL。

| 档位 | 字数 | 说明 | 触发场景 |
|------|------|------|---------|
| 短稿 | 200-500 | 短评 / 快报 / 观点输出 | 突发热点、单点判断、政策解读快讯 |
| 标准 | 500-1200 | 主力区间 | 教程、评测、政策解读、复盘 |
| 长稿 | >1200 | 深度稿 / 全景 | 横评、综述、争议追踪 |

**合理性判断三问**（05 审核岗执行，主笔写稿前自问）：
1. **信息密度**：删任何一段，读者是否少知道一件事？→ 不够则字数偏少；有多余则字数偏多
2. **读完用时**：与选题承诺匹配吗？（快讯 30 秒 / 教程 3 分钟 / 横评 8 分钟）→ 承诺 30 秒写了 1500 字即不合理
3. **节数匹配**：结构案定的节数 × 每节合理字数 = 当前字数？→ 差 >30% 需回结构案调整

**唯二 FAIL 条件**：
- 字数 < 200（疑似漏写，`gate-check.py` 硬拦）
- 主笔未写「元信息/字数」字段（读者与审核无法自证目标字数）

**历史对照**：v1 硬阈值 800-1200 → 曾逼出「凑字数」和「为达标硬压信息」，见 `复盘档案/`。

### 2. 备选标题

| 字段 | 标准 |
|------|------|
| 数量 | 5 个 |
| 字数 | 15-30 字 |
| 策略覆盖 | 5 种全覆盖：好奇心缺口 / 数据冲击 / 痛点共鸣 / 反常识 / 社交货币 |
| 支撑要求 | 每个标题必须在正文里有对应支撑段落（无支撑的删掉重写）|

**策略命名规范**：必须写成 `（策略名）`，四种等价写法均可：
- `（缺口）`（中文括号）
- `【缺口】`（方括号）
- `—— 缺口`（破折号 + 空格）
- `: 缺口`（冒号 + 空格）

### 3. 金句密度

- 每 1000 字 ≥1 处加粗
- 全文 ≥**2** 处加粗（底线）
- 金句必须从内容中自然生长，硬塞格言是最低级做法

### 4. 段落句数

- 每段 ≤3 句
- 手机一屏 3-4 段，超过就拆

### 5. AI 味评分

| 档位 | 分数 | 处理 |
|------|------|------|
| 放行 | ≤5 | 不改动 |
| 重写 ≥50% | 6-15 | 改稿 50% 以上 |
| 推倒重写 | >25 | 全部重写 |

**判定档位按模式**：
- 单人模式：`train-check.py --mode solo`，H14 只给参考分数、不卡关产出
- 审核模式：`train-check.py --mode strict`，走完整三档硬判定

**白名单豁免**：法规原文引用、必要列举（法条、触发条件、操作项）不计入 AI 味。

### 6. 占位符规范

- 标准占位符：`[待填写]`（预期行为，不扣分）
- 非标占位符：XX / ___ / xxx / 待补 / TBD（内容缺陷 = FAIL）
- 出现 `[待填写]` 时必须在文末追加 `## 信息缺口声明` 小节

## 脚本判定

- 字数：`gate-check.py`（H8 仅拦 <200；≥200 只报档位不 FAIL，合理性由 05 审核判）
- 段落 / 金句：`gate-check.py`（H9 / H12）
- 标题策略：`gate-check.py`（H10 标题策略覆盖）
- AI 味：`humanizer-check` 共享工具（H14 门禁，strict 模式硬判定）⚠️ 非本团队自有 skill
- 占位符：`gate-check.py`（占位符检查）
