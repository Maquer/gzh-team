# 团队技能梳理与查漏补缺方案

> **本文与前三份审计的分工**：AUDIT 查"文档对不对"，ROLE-REVIEW 查"边界对不对"，
> ROLE-GAPS-RESPONSE 查"漏洞修没修"。**本文查的是第三种问题：这个岗位有没有能力把活干完**——
> 技能是不是真在位、工具是不是真存在、缺口能不能被隔壁岗位补上。

## 0. 执行摘要

**一句话结论**：团队的知识密度很高（10 张角色卡的产出物标准、量化门槛、越界红线都写得扎实），
但**能力承载层是断的**——10 个岗位里 4 个的工具链存在"角色卡指向了不存在的文件"，
2 个岗位完全没有工具，2 个岗位完全没有培训技能卡；而 21 条交接契约
**20 条仍为 P1 待修**，且 52% 集中在视觉子链（09/10）——上游主链（01→02→03→04）
**连一条契约都没有**，另有 7 个交接点完全无契约定义。

### 五个最关键的发现

| # | 发现 | 严重度 | 证据 |
|---|------|--------|------|
| 1 | **6 个角色卡引用的工具路径不存在**（`gzh-api-push.py`、`humanizer-check.py`、`countdown-scheduler.py`、`gzh-toolkit`、`references/ai-detection-signals.md`、`references/dopamine-ladders.md`） | 🔴 阻断 | 目录实测（见 §4 TG-01） |
| 2 | **03 结构梳理与 08 回访是"零工具岗"**——03 是全队杠杆最高的一岗（决定"怎么讲"），08 是唯一的时间线岗（2h/24h/48h/72h） | 🔴 高 | 03-structure.md L59「无现成本地技能」；08-return.md L70 |
| 3 | **09 明镜 / 10 丹青 没有任何培训技能卡**（`training/skills/` 只有 01-09 旧编号卡），却承接了 21 条契约中的 11 条（52%） | 🔴 阻断 | 契约覆盖率统计（§8） |
| 4 | **7 条交接点无契约**，其中 `03→04 结构案` 和 `04→06 成稿` 是流水线主脉 | 🟡 高 | 契约缺口清单（§5.3） |

### 五个可立即执行的补强动作（本周可完成，全部零开发量）

1. **改指向，不开发**：把 6 个失效路径改指向已存在的真实工具
   （`humanizer-check.py` → `gate-H14-check.py`；`gzh-api-push.py` → `gzh-api-tui-song` skill；
   `countdown-scheduler.py` → `minis-scheduled` CLI）。
2. **认领 3 个"孤儿资产"**：`gate-H15-check.py`（已开发但 `docs/visual/tail-image-spec.md` 仍写"待开发"，
   且无任何岗位认领）、`gzh-cover-gen` skill（首图/尾图生成器）、`gzh-brand.py`（品牌视觉统一入口）——
   三者都是现成的，只是没有岗位说"这是我的"。
3. **补 2 张技能卡**：`training/skills/10-实拍视觉官.md`、`training/skills/11-视觉创意.md`，
   否则 11 条视觉契约永远无法考核。
4. **补 3 条主脉契约**：02→03（素材包）、03→04（结构案）、04→06（成稿）。
5. **定归属，删重复**：AI 味判定权收归 05，04 只交"分数 + 修改记录"，07 G7 第 8 项改为"读 05 的判定结论"；

## 1. 方法、证据源与口径

### 1.1 读什么

| 来源 | 用途 |
|------|------|
| `docs/roles/01-lead.md` … `10-creative.md`（10 张，共 725 行） | 岗位定位 / 核心技能 / 工具链 / 产出物标准的权威文本 |
| `TEAM.md`（630 行）、`docs/tools/*`、`docs/rules/*`、`docs/00-architecture/*` | 数值标准、门禁归属、时间线、RACI |
| `training/TRAINING.md` + `training/skills/*` + `training/baselines/*` | **工具熟练度的唯一硬证据** |
| `docs/audit/HANDOFF-CONTRACTS-20260926.md`（21 条契约） | 交接契约执行情况 |
| 仓库文件系统实测（`find` / `ls`） | 工具链缺失判定 |

### 1.2 熟练度五档口径（本文的核心标尺）

不自评"我熟不熟"，只用**工具是否真存在 + 是否有可判定的实测基线**两把尺子：

| 档 | 定义 | 判定依据 |
|----|------|---------|
| **S** | 有脚本 + 有实测基线 + 达标 | train-check 判定 PASS |
| **A** | 有脚本 + 有实测基线（未完全达标） | 基线存在，缺口已记录 |
| **B** | 工具/技能可用，但无实测基线 | 工具存在，`baselines/` 无该岗记录 |
| **C** | 工具存在但角色卡指向错误路径 / 部分不可用 | 目录实测 |
| **D** | 无工具，或角色卡指向的文件不存在 | 目录实测 |

**硬规矩（沿用 training/TRAINING.md §0 的边界）**：没有实测基线的，一律标 `⬜ 未实测`，
不填推测值、不写"应该没问题"。岗位是 prompt 驱动的，"感觉熟练"对产出影响为零。

### 1.3 自评口径声明

这是虚拟团队，**"技能自评"= 模拟该岗位视角的自我评估**。为了不让自评变成自夸，
每个岗位的自评结论都必须由以下三条之一的客观证据支撑：
① 训练基线（`training/baselines/`）、② 门禁脚本归属（`docs/rules/gate-mapping.md`）、
③ 契约覆盖率与漏洞回应状态（`HANDOFF-CONTRACTS` / `ROLE-GAPS-RESPONSE`）。
证据不足的自评项一律降级为"缺口"。

## 2. 各岗位技能矩阵（10 张）

> 每张卡结构统一：**定位 → 核心技能 → 工具链 → 产出物 → 自评（强项 / 缺口 / 工具熟练度 / 契约执行）**。
> 熟练度档位定义见 §1.2。

### 2.1 岗位 01 定规 — 负责人（Editor-in-Chief）

**定位**：全队方向盘。只定"写什么、为什么写、什么时候发"，不碰执行细节。全队唯一有权改账号定位与读者画像的人。

**核心技能要求**
1. 账号定位与读者画像定义（全队唯一权威）
2. 选题排期（触发条件驱动，非日历驱动：定位变化 / 复盘完成 / 用户指定）
3. 文章类型配比调优（工具测评 / 方法教程 / 观点 / 资讯）
4. 标题终选（从 04 的 5 个备选里选 1，须覆盖 5 种策略）
5. 发布否决权（G5 致命项为零后的最终签字）
6. 复盘判读与策略调整，输出到"不做清单"
7. 两道名单维护：选题库（含放弃理由）/ 不做清单（含**复评条件**）
8. 提醒任务审批（A 档自动登记 / B 档单点拍板 / C 档双签）

**工具链**：`apple-reminders`（选题排期表存清单）+ `docs/reminders/` 登记簿 + `countdown-scheduler.py add`（注册倒计时）

**产出物**：选题排期表（9 字段，含落选理由）+ 不做清单（4 字段，复评条件必填）

**自评（定规视角）**

| 维度 | 结论 |
|------|------|
| ✅ 强项 | ① 唯一在岗有**字段级判定基线**的决策岗——`train-check.py --role 06-负责人` 判 6 项，实测 83%（TRAINING.md §2 第 6 次培训）。② 提醒任务审批分级（A/B/C 档）是全队唯一带明确决策权重的机制。③ "复评条件必填"是全队少数几处真正防"决策遗忘"的设计。 |
| ❌ 缺口 | ① **字段完整性是唯一未达标项**：09-19 候选 1 缺 7 个字段、候选 2 缺落选理由（TRAINING.md §2 实测记录）。9 字段表里缺 7 个 = 排期表在关键位置是空的。② 提醒任务注册依赖的 `countdown-scheduler.py` **文件不存在**——审批通过后无法落地注册，审批链条在此断掉。③ 作为全队的上游源头，**没有任何出站契约指向 02/03/04**（21 条契约里只有一条 `01→07 选定标题`）。选题排完期，怎么派给衡度和矩尺，没有格式定义。 |
| 🛠 工具熟练度 | **B+** — `apple-reminders` skill 可用（B 档基线）；但注册脚本缺失（C 档）；决策岗自身有基线（拉回一档）。 |
| 🤝 契约执行 | 出 1（#4 选定标题）/ 入 1（#5 转选题候选），**两条均为 P1 待修**（#4：07 不知道哪个标题被选中；#5：要求写入 01 排期表中**不存在的"留言来源"列**）。**契约总数 2 条，全队倒数第二**。上游源头岗只贡献 1 条出站契约 = 派发环节是裸奔的；同时缺 `05→01 审核结论→放行签字`（HC-06），01 的否决权与 05 的否决权之间无契约支撑。 |

### 2.2 岗位 02 衡度 — 信息收集（Researcher）

**定位**：全队唯一对外部世界的接口。只交付**可验证的事实 + 可复用的素材**，不替任何人做价值判断。

**核心技能要求**
1. 每日热点扫描，命中赛道词才入库
2. 素材包产出（每条事实附来源链接 + 抓取日期）
3. 素材库维护（按主题分目录、可检索、可复用）
4. 置信度分级（A 官方 / B 署名媒体 / C 行业自媒体 / D 传闻）
5. 关键事实 ≥2 独立来源交叉验证
6. **主动找反例**（只找支持证据的收集必然产出偏稿）
7. 找不到就写"找不到"并列出已尝试的检索路径（拒绝沉默式漏报）

**工具链**：`re-souo-ju-he`（热榜）→ `anysearch` / `exa-search`（检索）→ `web-content-extractor`（正文提取）

**产出物**：素材包（8 字段，含置信度、抓取日期、可引用标记）；量化门槛 ≥8 条素材、≥3 条 A/B 级、文中每个数字 100% 有来源、反例 ≥1 条

**自评（衡度视角）**

| 维度 | 结论 |
|------|------|
| ✅ 强项 | ① **全队唯一四条工具链全部实测可用**的岗位——4 个 skill 全部存在于 `/var/minis/skills/`，无任何失效引用。② 置信度 A/B/C/D 分级 + "D 类不可引用"是硬规则，比多数团队的"标注来源"高一档。③ 反例强制 ≥1 条 + 找不到必须写检索路径，是防偏稿的结构性设计。 |
| ❌ 缺口 | ① **零实测基线**——`training/baselines/` 里"02 选题规划师"那次是 n=1 且只判通用规则（元话语/禁用词/紧迫诱导词/占位符 4 项），**必交付字段完整性完全未判**。也就是说 8 条素材 / 3 条 A·B 级 / 每个数字有来源这三条量化门槛**从未被脚本验证过一次**。② **没有一条出站契约**（只有 `09→02` 入站）。素材包是全队的输入源，交付给谁、什么格式、什么时机，全部空白。③ "素材库可检索、可复用"没有工具——已接入的 `second-brain` / Obsidian MCP 无人引用，素材库目前靠手建目录。 |
| 🛠 工具熟练度 | **B** — 工具链完整可用（B 档），无实测基线。注意：这是"工具最好、验证最少"的组合，风险比"工具差"更高——因为没人知道它输出了什么。 |
| 🤝 契约执行 | 出 0 / 入 1（#7 实拍图进素材包，P1 待修）。**全队唯一零出站契约的岗位**。 |

### 2.3 岗位 03 矩尺 — 结构梳理（Structurer）

**定位**：把"讲什么"变成"怎么讲"。产出可执行的骨架，一个字正文都不写。

**核心技能要求**
1. 核心论点提炼（一句话 ≤25 字，删掉整篇不成立才算立住）
2. 定唯一收益（多个收益 = 没有一个被满足）
3. 选结构模板（5 类：工具测评 / 方法教程 / 观点 / 资讯 / 复盘）
4. 铺骨架（节标题 + 本节要回答的问题 + 分配素材 ID + 字数预算）
5. 标金句候选位（具体金句由 04 写）
6. 设计开头钩子（数字反差 / 场景代入 / 反常识）
7. 设计结尾互动钩子（提问 / 投票 / 填空）

**工具链**：**无现成本地技能**。仅靠角色卡内嵌的 5 类结构模板库。

**产出物**：结构案（6 列：节 / 节标题 / 本节要回答的问题 / 用哪些素材 / 字数预算 / 金句位），含 `N×M` 字数预算初估与"每节都能回答读者读完能干什么"的判断规则

**自评（矩尺视角）**

| 维度 | 结论 |
|------|------|
| ✅ 强项 | ① **判断规则是全队最锋利的一条**："结构案里每一节都必须能回答'读者读完这一节能干什么'，回答不了 = 删掉或合并"——这是唯一一条可以直接证伪的结构标准。② 5 类结构模板各带"最容易犯的错"栏，是全队唯一"预先写好失败模式"的模板库。③ 越界红线写得最干净（不写正文/不补素材/不定标题/不追求章节数），四条全部有后果说明。 |
| ❌ 缺口 | ① **全队杠杆最高的一岗，工具配备为零**。结构案决定"怎么讲"，下游 4 个岗位（04/05/06/07）都按它执行，但 G3 结构门禁**无任何脚本**（gate-mapping 标注"人工判定"）。② **两条关键交接无契约**：`02→03 素材包`（收什么）与 `03→04 结构案`（全队最重要的单次交接）都不存在。结构案没有字段契约 → 主笔拿到的骨架格式全凭 03 心情。③ 字数预算与主笔"不追字数预算"的张力未消解（ROLE-GAPS-9 标 P1 待修）——结构案给了 `N×M`，主笔明确可以不追，这份预算的权威性是悬空的。④ 金句"候选位"标记（03 标 → 04 写）跨岗但无格式定义，落位率无法核验。 |
| 🛠 工具熟练度 | **D** — 无任何工具。这是 10 岗里唯一的"零工具"结构性缺口（另一个 08 是"零自动化"，见 §2.8）。 |
| 🤝 契约执行 | 出 1（#14 创意方案回签给 10，P1 待修）/ 入 1（#13 字数偏差说明，P1 待修）。**两条都在 P1 待修**，即入站出站同时不可靠。 |

### 2.4 岗位 04 管城 — 主笔（Writer）

**定位**：把骨架变成可读的正文。全队唯一被允许"润色"的人，也唯一被禁止改结构的人。

**核心技能要求**
1. **字数自判（必做第 1 步）**：写清类型 + 目标区间 + 合理性一句话理由，按"合理性判断三问"自检
2. 严格按结构案的节序与素材分配写
3. 短段落（每段 ≤3 句）
4. 金句 ≥2 处加粗，必须从内容自然生长
5. 5 个备选标题，15–30 字，5 种策略全覆盖，且**每个标题在正文有对应支撑段落**
6. 配图指导（位置 + 作用 + 期望效果 + 替代文字）
7. 结尾互动钩子（禁止乞讨）
8. AI 味检测（`--mode solo` 给参考分，白名单式只改命中处）
9. H3b 对齐（动笔前与 10 丹青对齐，15 分钟无共识升级给 01）
10. 动笔前走完 11 洞见维度

**工具链**：`bao-kuai-xie-zuo`（爆款写作 skill）+ `humanizer-check.py`（AI 味，**不存在**）+ `train-check.py`

**产出物**：成稿 Markdown（备选标题 5 个标策略 / 元信息含字数类型与理由 / 金句 ≥2 / 段落 ≤3 句 / 配图指导 4 要素 / 自检清单 6 项）

**自评（管城视角）**

### 6.4 培训体系的结构性建议（元层）

现有培训体系（技能卡 + `train-check.py` + 基线表）设计正确，但**覆盖严重不均**：

| 指标 | 现状 | 目标（P1 后） |
|------|:----:|:----:|
| 有技能卡的岗位 | 8/10（且 2 张指向已合并岗位） | 10/10 |
| 有实测基线的岗位 | **2/10** | 6/10 |
| 有必交付字段判定的岗位 | **1/9** | 9/9 |
| 能力项可被脚本判定的比例 | 04 主笔 9/9，06 负责人 6/6，其余 7 岗仅通用规则 4 项 | 每岗 ≥5 项 |

**关键判断**：SG-01 至 SG-19 的 19 条缺口里，**只有 1 条是真正的技能问题**（AI 味降味）。其余 18 条都是"知识已存在但没有落到可判定、可复用、可交接的容器里"。所以本方案的排序是：**先修承载（P0，2.5 人日），再消重复与建判定（P1，约 3 人日），最后做资产沉淀（P2，约 4 人日）**。反向做（先开班培训）会是无效投入——TRAINING.md §0 已经用 6 次实验 + 7 模型全失败实测证明过这一点。

### 8.5 本文的可证伪点

以下三条结论最容易出错，复核时应优先验证：

1. **SG-19 的"已修未落卡"判定**——若 09-photo.md 的触发条件实际在其他章节另有定义（本文只核对了"触发条件"段），则判定需修正。
