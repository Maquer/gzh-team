## 二、发现的问题（P0/P1/P2 分类）

### P0 — 阻断级（影响流水线可执行性）

**P0-1 实拍岗角色卡本体缺失**
`docs/roles/10-photo.md` 仅 4 行 stub，指向 `../../shared-roles/photo.md`，但该文件**不存在**（`find` 已确认全目录无 photo.md）。全团队唯一完整的 10 号岗定义只剩 TEAM.md §3.10，且 10-photo.md 的"做什么/红线/产出物/工具链"全部缺失。实拍岗（评测类稿件唯一真实视觉负责人）无法独立 prompt 注入。

**P0-2 对齐确认单模板指向错误角色**
`docs/手稿-对齐确认模板.md` 标题下写"主笔（管城）+ 排版（法度）共享"，"法度（排版）技术评估（不做创意决策）"。但 v2.2（CHANGELOG §21）已将 H3b 对齐对象改为"主笔 + 视觉创意（丹青）"。用此模板会把 H3b 交接单交给 06 而非 11，H3b 门禁（未签对齐单不得进④/④b）形同虚设。

**P0-3 视觉方案模板职责错位**
`docs/手稿-视觉方案模板.md` 末行"提交给：06-法度（执行生图+排版）"。v2.2.1（§22）后丹青已承担生图执行，法度只做排版+规范检查。模板若被实际填充，会把生图任务派回法度，重现 §20 已修复的角色漂移。

### P1 — 高影响（质量/可追溯性受损）

**P1-1 RACI 矩阵缺 4 列**
`org.md` RACI 仅 7 列（负/收/构/笔/审/排/发）。§13.2 早已记录"RACI 缺互动官列"未修，如今 08/09/10/11 四个岗均无列。10/11 的"创意决策""生图执行""实拍验真"在 RACI 上无 A/R 归属，与 §31"决策等级"机制脱节。

**P1-2 overview.md 对齐规则段落陈旧**
overview §2"新增对齐规则"写"管城提供配图需求，法度做创意决策（风格/色系/构图）+ 技术评估"。这是 v2.1.1 口径；v2.2 后创意决策归丹青。overview 与 11-creative.md 矛盾。

**P1-3 金句门槛三处口径不一（P0 级术语冲突，降 P1 因有明确数值）**
- standards.md §3：全文 ≥1 处加粗（底线）
- TEAM.md §3.4 产出物表：金句 ≥1 处加粗
- G7（07-publish）：≥2 处加粗金句
- contracts.md H4 打回条件：金句 <2
即 standards 允许 1 处，但 H4/G7 会因 1 处打回。需统一（建议以 G7 的 ≥2 为准，改 standards 底线）。

**P1-4 gate-mapping.md 缺 G3-G7 脚本归属**
gate-mapping 只列 G0/G8 + H11/H12/H14 + link-check/verify-all。G3(结构)/G4(成稿)/G5(审核)/G6(排版)/G7(发布清单) 无脚本行。表头声称"谁负责跑哪个门禁"，但这 5 个门禁无脚本，执行者只能靠人工勾——"规则写了但没被调用"的风险（表头自述目的）恰恰落在 G3-G7。

**P1-5 三张角色卡缺"产出物标准"表**
02-research/06-design/07-publish 的 role card 无"产出物标准"表（素材包/排版稿/发布记录）。TEAM.md §3.2/§3.6/§3.7 有，但 role card 单独注入 prompt 时该表缺失。subagent 派发（11-creative 头部注入段机制）拿不到产出物契约。

**P1-6 06-design.md 生图表未清除**
v2.2.1 把生图迁移到丹青后，06-design.md 仍保留整段"封面与配图生成"通道表（即梦/sensenova）+ 五条硬约束 + 比例适配。11-creative.md 也复制了同一张通道表。双份维护 = §00-architecture 设计原则"每个工具只定义一次"被违反，且未来通道变更需改两处。

**P1-7 CHANGELOG 章节断号**
§12、§14 缺失，且 §11 排在 §10 之前。front matter title 写 "10. v1.1" 但首个 H2 是 "## 11."。追溯"字数政策何时改"时需在断号中跳读，可追溯性受损。

### P2 — 中等（可读性/维护成本）

**P2-1 Gantt 标签错误**
gantt-chart.md "③c 创意 | T-2 上午→中午" 但时间窗 13:00→15:00 属下午。"上午→中午"标签与小时值矛盾。

**P2-2 Gantt 资源日历乱序**
日历按 定规01/衡度02/矩尺03/管城04/权衡05/**丹青11**/法度06/维缆07/接引08/筹校09/明镜10 排列，11 插在 05 与 06 之间。按编号序更易读；明镜(10) 无时间条只写"(评测类激活)"。

**P2-3 04-writer.md 断句**
AI 味段"…把「引用块内」计入豁免。：只改命中处"——"豁免。"后接"：只改命中处"，句号与冒号连用，后半句"只改命中处，未命中逐字保留"成为孤儿片段。

**P2-4 04-writer.md step 0 编号**
"做什么"列表从 0 起（字数自判），后接 1-7。step 0 是 v2.0 后插入的，编号不连续易在 prompt 注入时被 model 当作"可选前置"忽略。建议并入 step 1 或标注"必做第 1 步"。

**P2-5 11-creative.md 灵魂段自相矛盾**
文末"岗位灵魂：不画具体的图，只定图的方向"——但"做什么"第 5 项是"执行生图 + Pillow 后处理"。"不画具体的图"与"执行生图"字面冲突，会误导 prompt 注入。

**P2-6 08/09 无 KPI 数值**
08 互动官"2h 回复全部留言"来自 CHANGELOG §10.1 的 `[拍]` 标签（13.3 已标"无依据"），role card 未带基线。09 数据分析师"偏离基线 ≥2 倍"但基线未建立（CHANGELOG §18 明确"不可用"）。两岗指标悬空。

**P2-7 quickstart.md 编制陈旧**
"不是所有人都能凑齐 7 人"——现 11 岗。最小 1 人版仍说"8 个角色全部自己干"。10/11 岗加入后未更新最小配置表（10/11 在 1 人版如何降级无定义）。

**P2-8 TEAM.md Index 段标记异常**
文末 auto-generated Index 中 CHANGELOG/contracts/overview 三项 token 标记 "OVER"，提示该三层内容超预算被截断风险。需确认 split.py 未实际截断关键门禁文本。
