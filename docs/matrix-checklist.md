## 一、Gate-check 门禁（生产环节，自动执行）

| 编号 | 名称 | 类型 | 检测方式 | 阻断级别 | 状态 |
|------|------|------|---------|---------|------|
| H8 | 字数达标 | 安全 | `gate-check.py` 实测中文字数 | BLOCK <200字 | ✅ |
| H9 | 段落≤3句 | 质量 | `gate-check.py` 逐段计数 | WARN | ✅ |
| H-禁 | 禁用词 | 安全 | `gate-check.py` 匹配9词 | WARN | ✅ |
| H-元话语 | 元信息泄漏 | 安全 | `gate-check.py` 正则扫描 | BLOCK | ✅ |
| H-注入 | 占位符残留 | 安全 | `gate-check.py` 正则扫描 | BLOCK | ✅ |
| H-占位符声明 | 缺口声明 | 完整性 | `gate-check.py` 检查`[待填写]`有无对应小节 | BLOCK | ✅ |
| H-策略 | 标题策略覆盖 | 质量 | `gate-check.py` 括号标注计数≥5 | WARN | ✅ |
| G8 | 结构多样性 | 质量 | `gate-check.py` 检测连续同类骨架+禁用起手式/收尾式 | WARN | ✅ 新增 |

**执行位置**：主笔交稿前必跑，审核岗独立复核

## 五、多模型评审分工

### 评审问题（当前）

1. **门禁过载？** H8/H9/G8等十余项并行，主笔是否应合并执行？
2. **AI味检测准确性？** H14的lieflat规则在政策类稿件误报率高，是否需行业白名单？
3. **结构多样性如何量化？** G8的连续同类检测是否需要更细粒度（不仅看骨架类型，还要看开头句式、结尾方式）？
4. **哪些门禁可以降级为WARN？** 当前BLOCK仅3项（H8<200字/H-注入/H-元数据），是否过于宽松？

### 模型分工

| 模型 | 角色 | 关注维度 |
|------|------|---------|
| model-a (DeepSeek-V4) | 主编视角 | 整体架构、流程合理性、冗余项识别 |
| model-b (GLM-5.3) | 审核视角 | 风险覆盖、误报率、执行成本 |
| model-c (Qwen3.8) | 技术视角 | 脚本实现、自动化程度、扩展性 |
| model-d (DeepSeek-V4-Flash) | 主笔视角 | 创作自由度、修改成本、反馈及时性 |
