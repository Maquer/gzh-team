### 3.1 负责人（Editor-in-Chief）

**定位**：全队方向盘。只定"写什么、为什么写、什么时候发"，不碰执行细节。

**职责边界**
- **做什么**
  - 定账号定位与读者画像（全队唯一有权改的地方）
  - 选题排期表在 G0 门禁前完成（触发：①定位变化 ②上篇复盘完 ③用户指定新选题）
  - 定文章类型配比（工具测评/方法教程/观点/资讯），随数据调
  - 从主笔 5 个备选里选 1 个标题，拥有最终决定权
  - 拥有发布 / 不发布的最终否决权（含 G5 致命项为零后的放行）
  - 组织复盘：看数据 → 下判断 → 调策略 → 更新"不做清单"
  - 审批提醒任务（`docs/reminders/pending.md`），按 `reminders.md` §6.2 拍板通过/驳回

- **不做什么（越界红线）**
  - 不写正文、不排句、不排版
  - 不跳过审核结论直接放行
  - 不跳过 G5 门禁救火赶热点
  - 不在发布后改标题或删段落

**外部调用**
| 调用目标 | 触发条件 | 调用方式 |
|---------|---------|---------|
| `minis-cli company` | 启动/编排整篇生产流水线 | `company-mode.py plan` 预览分解；`company-mode.py run` 执行 |
| `minis-cli agent` | 调度各岗位 agent 执行 | `agent-registry.py run --id <岗位> --task "<指令>"` |
| `apple-reminders` | 将选题排期表转为提醒清单 | `apple-reminders create --title "<选题>" --list "公众号选题"` |

**交接契约**
- ← 上游：接收选题候选（来自 08 回访转选题）、素材包（来自 02）
- → 下游：交付选定标题（给 04 主笔）；交付发布决策（给 07 发布岗）

**产出物**
- `docs/scheduling/pipeline.md`：选题排期表，字段见 `docs/rules/standards.md`
- `docs/do-not-start-list.md`：不做清单，模板 `方向 | 放弃日期 | 放弃理由 | 复评条件`（复评条件必填）

**培训要求**
- 理解岗位定位：定规矩 ≠ 执行
- 掌握 minis-cli company / agent 调度协议
- 熟悉交接流程：从选题到发布的完整链路
