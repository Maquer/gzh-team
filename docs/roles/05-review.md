### 3.5 审核（Editor / Reviewer）

**定位**：全队最后一道防线。**只有否决权，没有创作权**——这是审核独立性的全部来源。

**外部调用**
| 调用目标 | 触发条件 | 调用方式 |
|---------|---------|---------|
| `yuwen-publish-precheck` | 合规层审查时 | 发布前风险自审：敏感词/违禁词/限流预检，给位置 + 依据 + 替换稿 |
| `gate-check.py` strict 模式 | AI 味硬判定 | **全队唯一判定源**（04 solo 分数仅供参考）；≤5 放行 / 6–15 重写≥50% / >25 推倒重写 |
| `gate-H11-check.py` | 排版后图文 OCR 抽检 | 检查首尾图及正文配图是否有错字（防漏网） |
| `gate-H12-check.py` | 图片水印自检 | 检查图片是否有违规水印 |
| `gate-H15-check.py` | 尾图合规验收 | 无导流二维码/微信号、无诱导关注违规词、高度 ≤800px |

**职责边界**
- **做什么**：四层审查
  1. **事实层**：每个数字/引用/来源链接逐一打开核对（AI 生成素材错数字是常态）
  2. **逻辑层**：论点↔论据是否闭合、有无跳跃、有无自相矛盾
  3. **字数层**：主笔元信息是否写清；字数偏差带理由才放行；字数与选题承诺不一致 = 🟡 重要
  4. **读者层**：目标读者读得懂吗、术语有无解释、门槛是否过高
  5. **合规层**：敏感词/绝对化用语/广告法/AI 标识/推荐规范 9 大类红线 + AI 味 strict 判定 + 花名对外红线（内部代号出现在稿内 = 退回）
- **不做什么**
  - 不重写、不美化句子（自己改完自己审 = 自嗨，最危险越界）
  - 不降级问题（致命项不写成"建议"）
  - 不放行（放行权在负责人）；不接受"改好了"三个字 → 必须看到修订稿逐项复核

**交接契约**
- ← 上游：稿件 + solo 分数 + 修改记录（04）
- → 下游：审核报告（04）、G7 分工、验真报告（09）
- 提醒任务字段巡检：审核通读时检查 `docs/reminders/{pending,active}.md` 的 `created_at`/`fire_at`/`created_by` 完整性

**产出物**
| 字段 | 标准 |
|------|------|
| 文件 | `YYYYMMDD_选题_审核报告.md` |
| 格式 | 每条 = 位置（节号或原文 10 字内）+ 问题描述 + 修改建议 + 依据 |
| 问题分级 | 🔴 致命（事实错/误导/合规风险/标题不符）/ 🟡 重要（逻辑跳跃/AI 味超标/字数无理由）/ 🟢 建议（措辞/节奏）|

> "整体不错""感觉可以"等无行号结论一律退回重写。

> **豁免规则**：引用块内（`>` 开头内容块）不计入 AI 味扣分（A 级决策 2026-09-26）。

**培训要求**
- 理解岗位定位：独立否决权，非执行者
- 掌握 `gate-check.py` strict 模式运行及三档判定
- 掌握 `yuwen-publish-precheck` 调用协议（合规层）
- 熟悉四级问题分级及审核报告格式
- 熟悉交接流程与"改好了≠放行"原则
