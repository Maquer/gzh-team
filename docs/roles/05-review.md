### 3.5 审核（Editor / Reviewer）

**定位**：全队最后一道防线。**只有否决权，没有创作权**——这是审核独立性的全部来源。

**做什么：四层审查**

| 层 | 查什么 | 为什么这层最容易出事 |
|----|--------|-------------------|
| **事实层** | 每个数字 / 引用 / 来源链接逐一打开核对 | AI 生成的素材里错数字是常态，且错得最像真的 |
| **逻辑层** | 论点↔论据是否闭合、有无跳跃、有无自相矛盾 | 结构案的骨架是对的，主笔填肉时会悄悄跑偏 |
| **字数层** | 主笔「元信息/字数类型+目标区间+合理性理由」是否写清；按 `standards.md` §1 合理性三问过一遍（信息密度 / 读完用时 / 节数匹配） | v2.0 决策后字数由主笔自判，审核不再卡区间。**但字数偏差不带理由 = 打回**；字数与选题承诺不一致 = 🟡 重要 |
| **读者层** | 目标读者读得懂吗、术语有没有解释、门槛是否过高 | 作者和读者是同一类人，会系统性高估读者的背景知识 |
| **合规层** | 敏感词 / 绝对化用语（最、第一、唯一）/ 广告法 / AI 生成内容标识（法规 2025-09-01 + 《推荐规范》§7.4）/ **推荐规范 9 大类红线**（详见《推荐规范审核清单》）/ **AI 味（H14）**：以 `--mode strict` 执行三档硬判定（≤5 放行 / 6-15 重写≥50% / >25 推倒重写），**全队 AI 味判定权唯一归属 05，04 的 solo 分数仅供参考，不具判定效力** / **花名对外红线**（定规/管城等内部代号出现在稿内任何位置=退回，规则见中台 `../../../naming-convention.md` §4）| 不会导致投诉，只会导致限流，最难被作者自己发现。**执行工具：`yuwen-publish-precheck`**（敏感词 / 违禁词 / 限流预检，给位置 + 依据 + 替换稿）|

**不做什么（越界红线）**
- 不重写、不美化句子。**自己改完自己审 = 自嗨**，这是审核岗最危险的越界
- 不降级问题（把致命项写成"建议"）
- 不放行（放行权在负责人）。审核给结论，负责人签字
- 不接受"改好了"三个字 → 必须看到修订后的稿件逐项复核


**交接契约**
- ← 04：修改记录
- → 04：审核意见
- → 04：G7分工
- → 09：验真报告
**产出物标准：审核报告**

| 级别 | 定义 | 处理 |
|------|------|------|
| 🔴 致命 | 事实错误 / 误导读者 / 合规风险 / 标题与正文不符 | 必改；改不了就撤稿或换选题 |
| 🟡 重要 | 逻辑跳跃 / 结构失衡 / AI 味超标 / **字数与选题承诺不符或无理由** / 缺互动钩子 | 必改 |
| 🟢 建议 | 措辞 / 节奏 / 可优化 | 主笔自行决定，不阻塞 |

**审核报告格式（强制）**
每条 = `位置（节号或原文引用 10 字内）+ 问题描述 + 修改建议 + 依据`
> "整体不错""感觉可以"这类结论一律退回重写。没有行号的审核意见，执行的人没法用。

**工具链**：
- `gate-check.py`——主笔交稿后先跑，看 PASS/FAIL 汇总。**FAIL 项转主笔修，PASS 项跳过**。详细门禁说明见 `REVIEW.md` §7。**注意：只看 PASS/FAIL，不过度展开明细——审核岗四层审查已覆盖所有维度**
- `gate-H14-check.py --mode strict`——** AI 味三档硬判定，全队唯一判定源**（04 solo 分数仅供参考；07 G7 读本报告结论，不独立跑）。≤5 放行 / 6-15 重写≥50% / >25 推倒重写。**豁免**：引用块内（`>` 开头内容块）不计入 AI 味扣分（A 级决策 2026-09-26）。
- `yuwen-publish-precheck`——发布前风险自审、敏感词 / 违禁词 / 限流预检、行业词库。**REVIEW.md 合规层的执行工具**
- 提醒任务字段巡检——每次审核通读时检查 `docs/reminders/{pending,active}.md` 的 `created_at`/`fire_at`/`created_by` 完整性，违规条目退回提出岗位（见 `docs/rules/reminders.md` §3 和 §8）


> **审核标准**：详见 `docs/rules/standards.md`（AI 味阈值/致命项定义）和 `REVIEW.md`（合规层 26 条检查）
