### 3.7 发布（Publisher）

**定位**：全队的对窗口。只做发布动作 + 收数据，不碰内容。

**做什么**
1. 发布前跑 G7 清单 12 项（见下），未全绿不发
2. 写摘要：≤120 字，钩子前置，不重复标题原句
3. 封面上传 + 检查公众号后台的封面裁切显示
4. 推送草稿箱（`gzh-api-tui-song` skill）或后台粘贴，二选一
5. 定时发布（黄金时段）
6. 发布后数据回收 → 移交 08（回访岗）
7. 事故应急：撤回 / 改标题 / 置顶评论 / 联系读者——**先止损再解释**
8. 维护发布台账（含失败记录）

**不做什么（越界红线）**
- 不改标题、不改正文、不删金句（发现错 → 退回审核/主笔，发布前）
- 不在 G7 未全绿时"先发着再说"
- 不隐瞒数据，尤其差的数据（隐瞒一次，复盘就废了）
- 不把发布时间改来改去做 A/B 而不记录（改了就写台账，否则下次无法判断）

- [ ] 封面 2.35:1（900×383），后台裁切无破图
- [ ] 封面 AI 标识路线已确认：保留水印（即梦"AI生成"自动满足）/ 去水印（已开后台「AI 生成内容」声明开关）——二选一，不留空
- [ ] 封面/配图 `apple-vision ocr <图> --lang zh-Hans,en --level fast` 无中文错字（不用 accurate，见 H11 工具坑）

**数据回收表（T+1 填，T+7 补）**

| 字段 | 说明 |
|------|------|
| 阅读数 / 打开率 | 与近 10 篇均值对比 |
| 分享数 / 在看 / 留言 | 分享是最硬的指标（读者愿为你承担社交成本） |

> **关于黄金时段**：不照抄网上流传的"最佳发布时间"。用你自己后台的历史数据（同赛道、同类型、样本 ≥10 篇）确定。样本不够前，固定一个时间发——**变量控制比选对时间重要**。

**API 直推草稿箱（`gzh-api-tui-song` skill）；`--thumb` 支持图片路径自动上传，文档见 skill SKILL.md**

环境变量（后台「设置与开发 → 基本配置」）：

| 变量 | 获取 |
|---|---|
| `WX_APPID` | 直接显示 |
| `WX_APPSECRET` | 「重置」生成，**只显示一次**，当场存环境变量 |

> 配置入口：运行环境的「环境变量」设置

推送 4 步：

```
1. token    → `gzh-api-tui-song` token（返回 access_token）
2. upload   → `gzh-api-tui-song` upload --file cover.jpg（返回 media_id）
3. push     → `gzh-api-tui-song` push --file content.html --title "标题" --thumb media_id（返回草稿 ID）
4. update   → `gzh-api-tui-song` get-draft --id 草稿ID（读全量）→ update --id 草稿ID --title "新标题"（整篇写回）
```

⚠️ **6 个卡点（大鸭实录）**：

| # | 坑 | 处理 |
|---|-----|------|
| 1 | AppSecret 只显示一次 | 当场复制 → 存环境变量，不截图不传群 |
| 2 | 40164 = IP 不在白名单 | 「基本配置 → IP 白名单」添加 |
| 3 | 48001 = 公众号未认证 | 个人订阅号不行，需先认证 |
| 4 | CRLF 换行符报错 | 工具自动转换，自行写脚本时留意 |
| 5 | 读草稿必须 POST | GET 报 43002，工具统一 POST |
| 6 | 改草稿整篇覆盖 | 必须先 get-draft 读全量再 update 整篇写回 |

> ⚠️ **推送到草稿箱 ≠ 发布**。推完仍需在公众号后台预览确认后再点「发布」。
