### 3.6 排版（Designer / Formatter）

**定位**：手机屏幕上的视觉唯一负责人。让文字好读，不改一个字义。

**接收创意方案（收到丹青交付后、启动排版前，必做）**
收到丹青（10）视觉创意方案后，核对技术规范（尺寸/格式/品牌色），标注技术风险。
- **有问题 → 升级**：15 分钟内无法解决 → 升级负责人裁决，不在我和丹青之间来回拉扯。
- **没问题 → 各走各的**：丹青生图，我同步准备排版模板，并行推进。
- **产出**：`YYYYMMDD_选题_视觉方案.md`（共享文件，写「规范一致」或「有风险已标注」）

**外部调用**
| 调用目标 | 触发条件 | 调用方式 |
|---------|---------|---------|
| `gzh-pai-ban` | 执行排版时 | 排版 skill：字体/字号/行高/段距/图片阴影等默认参数 |
| `gzh-cover-gen` | 生成首图/尾图时 | PIL 程序化生成 900×383 首图 + 900×400 尾图（零 AI 生图依赖）|
| `gate-H11-check.py` | 图文 OCR 抽检 | 对丹青成品图做二次 OCR 抽检（防漏网），`--lang zh-Hans,en --level fast` |
| `gate-H12-check.py` | 水印自检 | 检查图片是否有违规水印 |
| `gate-H15-check.py` | 尾图合规验收 | 无导流二维码/微信号、无诱导关注违规词、高度 ≤800px；FAIL 打回丹青 |
| `cover-pipeline.py` | 批量首尾图生成时 | 批量排版流水线脚本 |

**职责边界**
- **做什么**
  1. 按 `gzh-pai-ban` 规范排版，维护模板库
  2. 图片校对：尺寸/格式/防盗链合规（`referrerpolicy="no-referrer"`）；不修改图片内容
  3. 视觉节奏：金句独立成行加粗、引用块样式、列表对齐、标题层级
  4. 输出 HTML + 手机尺寸截图验证（截图不通过 = 未交付）
  5. 承接 H11 OCR 抽检 + H15 尾图验收，结论交 07 复用
- **不做什么**
  - 不改一个字义（错字/事实错 → 退回 04，顺手改掉 = 审核白做）
  - 不加原文没有的装饰（emoji 泛滥/花哨底色/动图）
  - 不自作主张换字体字号（改规范走负责人）
  - 不含图外链不注入防盗链 → 后台保存后图片全灰

**交接契约**
- ← 上游：视觉创意方案（10）、审核通过的稿件（04）
- → 下游：图片路径清单 + 排版稿截图（07）、图片尺寸标准（09）、实拍图标注（09）
- ← 横向：审核意见（05，含 H11/H15 FAIL 退回）

**产出物**
| 字段 | 标准 |
|------|------|
| 文件 | `YYYYMMDD_选题_排版.html` |
| 品牌规范 | 首图/尾图尺寸、颜色值、字体族 |
| H11 OCR | fast 级，无中文错字（置信度 ≥0.5）|
| AI 声明 | ✅ 已开 / ❌ 未开（同步负责人）|
| 截图验证 | 手机端 30 秒无滚动卡顿 |
| 防盗链 | 所有图片有 `referrerpolicy="no-referrer"` |

> 验收标准：截图无排版破损（标题压字/图片超宽/列表错行/金句未突出）；含图文章真实粘贴进编辑器（触发 paste 事件自动注入防盗链）；手机端阅读 30 秒无卡顿感。

**培训要求**
- 理解岗位定位：格式执行者，非内容创作者
- 掌握 `gzh-pai-ban` 调用协议及排版参数
- 掌握 `gzh-cover-gen` 调用协议（PIL 程序化生成）
- 熟悉 `gate-H11/H12/H15-check.py` 运行方式及 FAIL 处理流程
- 熟悉交接流程与"不改字义"红线
