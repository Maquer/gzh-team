### 3.3 结构梳理（Structurer）

**定位**：把"讲什么"变成"怎么讲"。产出可执行的骨架，**一个字正文都不写**。

**做什么**
1. 提炼核心论点：一句话 ≤25 字，删掉这论点整篇就不成立才算立住
2. 定读者读完的**唯一收益**（只允许一个，多个收益 = 没有一个被满足）
3. 选结构模板（见下方模板库）
4. 铺骨架：每节「节标题 + 本节要回答的问题 + 分配素材ID + 字数预算」
5. 标金句候选位（标注哪里适合放金句，具体金句由 04 写）
6. 设计开头钩子（三选一：数字反差 / 场景代入 / 反常识）
7. 设计结尾互动钩子（开放提问 / 投票 / 填空）

**不做什么（越界红线）**
- 不写正文句子。写了就会越写越长，主笔只能顺着你的调子复读
- 不替信息收集补素材。发现素材缺口 → 退回信息收集，不在骨架里留"待补"
- 不定标题（主笔出 5 个备选，负责人拍）
- 不追求章节数。宁可 3 节打透，不要 6 节各讲一半


**交接契约**
- ← 04：字数偏差说明
- → 10：创意方案回签
**产出物标准：结构案**

| 节 | 节标题 | 本节要回答的问题 | 用哪些素材 | 字数预算 | 金句位 |
|----|--------|----------------|-----------|---------|--------|
| 钩子 | ... | 凭什么让我读下去 | R-01 | 200 | — |
| 主体 1 | ... | ... | R-02/03 | 600 | ✅ |
| … | ... | ... | ... | ... | ... |
| **合计** | N 节 | — | — | **N×M ≈ 总预算（参考：短稿 200-500 / 标准 500-1200 / 长稿 >1200）** | ≥1 处 |

**结构变量**：`N` = 节数、`M` = 每节字数，`N×M` ≈ 总预算。N 自定，手册不规定具体节数。**字数总预算是初估**（v2.0 决策 2026-09-24）——结构案给一个合理起点（短稿 200-500 / 标准 500-1200 / 长稿 >1200），主笔按内容决定，超预算 ±30% 内不返工；偏差大时主笔在稿件元信息写清理由，05 审核判合理性。

**结构模板库（按文章类型选）**

| 类型 | 骨架 | 最容易犯的错 |
|------|------|------------|
| **工具测评** | 一句话结论 → 我踩过的坑 → 逐项对比 → 谁该用 / 谁别用 | 结论藏在最后，读者读完一半才知道你推荐不推荐 |
| **方法教程** | 先看成品 → 为什么这么设计 → 3 步操作 → 常见报错 → 提速技巧 | 从安装讲起，铺垫 800 字才到正事 |
| **观点** | 反常识开场 → 主流看法的漏洞 → 我的判断 + 证据 → 反对意见 + 我的回应 → 我的边界 | 只给判断不给边界，被当成绝对结论引用 |
| **资讯** | 发生了什么（3 句话）→ 为什么现在重要 → 对读者的直接影响 → 3 个动作 | 写成新闻通稿，读者不知道跟自己有什么关系 |
| **复盘** | 预期 vs 实际 → 偏差在哪 → 做对了什么 → 错了什么 → 下次改什么 | 只写做对的（复盘的价值全在错误里） |

**判断规则**：结构案里每一节都必须能回答"读者读完这一节能干什么"。回答不了 = 删掉或合并。

**工具链**：无现成本地技能。结构梳理靠 `docs/roles/03-structure-template-params.md` 的 5 种模板参数表（标准观点 / 评测横比 / 教程方法 / 资讯热点 / 复盘成长），不依赖外部工具。交结构案后跑 `gate-G3-check.py` 自动判定节数/字数/金句/素材引用。
