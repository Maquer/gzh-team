# 选题信息

| 字段 | 内容 |
|------|------|
| 选题 | 最好的 AI 工具，不告诉你它做不到什么 |
| 目标读者 | 25-40 岁用 AI 做内容的博主/开发者，正在给 Agent 装工具或写 Skill |
| 读者痛点 | 装了一堆工具，出问题时不知道是"工具没做到"还是"自己用法错"，反复怀疑、反复浪费 token 排障 |
| 预期收益 | 带走 4 条可执行的"能力边界自披露"检查清单，下次接任何工具/写 Skill 前 10 分钟就能判断"这个工具值不值得信" |
| 素材可得性 | ✅ 公开（GitHub 源码 5/5 坐实，320 文件 23.7k★，MIT） |
| 风险 | ① 水印移除是敏感领域，需明确"本工具不教去除他人版权水印，只治你自己的工作流"；② 读者若无 Agent 工具使用经验，开头需 1 个具体场景锚定 |
| 优先级 | 1 |
| 状态 | G1 待生产 |

## 主论点

一个工具说"我检查了什么、没检查什么、外部工具能补什么"，比说"我全都能做"可信 10 倍。
**能力边界自披露，是 AI 工具工程里最被低估的维度。**

## 核心论证链

```
[钩子] 你问过 Agent 的工具库"你确定能做到吗"吗？
  ↓
[定义] "能力边界自披露"= 工具主动告诉你它做不到的事 + 做到什么程度 + 谁来兜底
  ↓
[证据 1] archify 66k★ / MIT / 09-23 iSH 实测：82 条 rule code + 119 测试 + 4 版本矩阵 + 导出 WebM 逐帧校验 + 冻结候选 SHA-256 收据 —— "我验过几何/模式/制品完整性，没验过语义"明说
[证据 2] watermarks-remover 23.7k★ / MIT / 源码 320 文件 5/5 坐实：ethics.md 四段 + /capabilities 端点 + test_c2patool_report.py 覆盖 + stealer/ 闭环测量
[证据 3] 对照反面：Vercel Skills 30.6k★ 一行装到 73+ Agent，SKILL.md 规范（agentskills.io）—— 能力边界声明是可选字段，多数 Skill 写了"能做"没写"做不到"
[推论] 功能层（能做什么）是同质化的；治理层（说清做不到什么）才是分水岭
[可操作结论] 4 条检查清单（见下）
[读者行动] 下次接工具/写 Skill 前，用清单 10 分钟过一遍
```

## 4 条"能力边界自披露"检查清单（读者带走的核心交付）

| # | 检查项 | 判断标准 | 对应范例 |
|---|--------|---------|---------|
| 1 | **能力端点**：工具是否有一个"我当前装了哪些 backend"的自报告接口？ | 有 `/capabilities` 或等价段落，且文档说明"只在 backend present 时才推荐该能力" | watermarks-remover `/capabilities` |
| 2 | **证据分层**：报告是否把"可验证"和"尽力而为"分成不同等级？ | 有 `verifiable` / `best_effort` / `out_of_scope` 三档字段，且读者可分辨哪档是硬保证 | watermarks-remover 报告字段分层 + archify 布局层 vs 语义层 |
| 3 | **降级行为**：缺依赖时是静默失败还是明说"够不到哪一层"？ | 有诚实降级告警（exit code / 日志 / 报告），不是 try-except 吞掉 | watermarks-remover 语义化退出码 2/1/3 |
| 4 | **闭环测量**：有没有"自己种已知缺陷→自己修→测修复程度"的内部验证环？ | 有 `stealer/` 或等价 fixture + 回归测试，且每轮标注"跑了哪几层" | watermarks-remover stealer + archify CI WebM 逐帧 |

**金句候选**：
- "功能层是同质化的，治理层才是分水岭。"
- "一个工具明说它做不到什么，比它说它能做什么，可信 10 倍。"
- "4 条清单，10 分钟，判断一个工具值不值得信。"

## 角度定位

- **不写**：水印移除的具体技术（iSH 跑不了，读者也不关心）、C2PA 元数据机制、统计水印改写算法
- **只写**：治理层 4 个维度的"怎么判断"框架 + 2 个正面范例（archify / watermarks-remover）+ 1 个反面（Vercel Skills 规范里能力边界是可选）
- **可信度叙事**：明说"我在 iSH 上跑过 archify，两个坑（realpath ENOENT + renderer 错误退化），跑通后 820KB 自包含 HTML 落 workspace"——不是空谈，是实测

## 反例（≥1 条）

- **反面**：某个工具/Skill 文档里全是"能做 X / 能做 Y / 能做 Z"，没有一段"做不到什么 / 什么情况下会降级 / 谁兜底"——读者用了踩坑才发现。**Vercel Skills 规范本身**：agentskills.io 的 SKILL.md frontmatter 里"能力边界"是可选字段，多数 Skill 没填 → 默认读者假设"没写=全都能做"，这是行业默认假设的反面。
- **内部反例**（可信度）：我 09-23 接入 archify 时，eval-gate 对它 71/100 PASS 但 meta-skill 31/100——**假阴性根因**是我 FME/HAB 正则全用中文（"因为/根因/兜底"），archify SKILL.md 是英文 → 只命中 `fallback` 1 词得 1/10。**实际** archify 的失败机制编码是全库最强（禁止非零退出称成功 + iteration budget + 2 轮不改善即停并如实报告）。→ 这条可进正文作"我自己的工具也犯过'没读语义层'的错"的可信度锚点。
